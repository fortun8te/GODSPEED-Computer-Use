# Local observation capture

The optional proxy-side recorder, `scripts/godspeed_observation_capture.py`, saves filtered visible native app-window text and action metadata locally. Enable it only with explicit authorization for the intended app and data scope. A proxy must deliberately load the recorder; installing the Godspeed app does not configure it. Existing proxy processes keep their loaded code until they end. A proxy that honors `GODSPEED_OBSERVATIONS=0` can be started with recording disabled.

Records go to `~/.godspeed/observations/<session>.jsonl`, in a 0700 directory with 0600 files. Each connection has a random session ID and per-session keyed target and app fingerprints. The recorder includes time, action type, click labels, requested batch step types and click labels, requested-check presence, error or acknowledgement, and linked native app-state reads. It includes filtered visible text and a role count for native `get_app_state`. The following read is linked to the most recent action on that app; a changed view is only a change, not evidence of the intended outcome. Requested batch steps are not proof they ran. `task_verification: not_checked` means unknown, not failed or successful.

The recorder ignores image blocks, raw argument payloads and clipboard content. It redacts editable-field subtrees, suppresses text in secure windows, and stops saving all text for the rest of that connection after typed input or clipboard use, since text can be echoed or transformed. It filters common credential formats. This is not a guarantee that all private information or secrets are identifiable: permitted visible text can include private content, and manually entered or echoed content from another connection may appear outside an editable control. Review locally before creating a dataset or sharing anything. Browser tool calls currently have only metadata: browser page text and browser action steps are not captured. Screenshots are not saved by this recorder, so it cannot supply vision-training images.

The recorder does not delete older records. It stops a session at 20 MiB and stops accepting new records when checked directory size reaches 2 GiB, reporting write failures on proxy stderr. The directory cap is checked on the first call and every 128 calls, so concurrent sessions can temporarily exceed it. Keep reviewed exports separate, preserve source session IDs, use separate workflow families for train and evaluation, and require independent success checks or human review. A changed screen, model decision, requested step, or tool acknowledgement is not a gold label. The older `~/.godspeed/learning` and `~/.godspeed/trajectories` stores have separate policies and retention.

Privacy caveat: Godspeed's existing `LearningLog` can separately save vision crops when its image option is enabled. Set `OPEN_COMPUTER_USE_LEARNING_LOG_IMAGES=0` in the environment of the process that owns the learning log to disable those image records. That setting does not change the environment of a separate long-lived app agent or remove existing records.

Validation: run `python3 -m unittest scripts/tests/test_godspeed_observation_capture.py -v`. Proxy integration must also be tested through a fresh connection because an existing connection will not load new Python code.
